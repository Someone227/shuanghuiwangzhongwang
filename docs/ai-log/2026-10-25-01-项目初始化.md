## 本次决策

### 1. 选题：政策资格匹配器「能申吗」

三个候选方向对比后选择本方向，理由：
- 真实痛点，受众明确（学生 / 市民查政策资格）
- AI 不可替代：非结构化政策原文 → 结构化条件树 → 人与条款的逐条匹配推理
- 差异化：往届同类「办事清单助手」只提取清单，不做**个人资格判定与溯因**
- 演示性强：贴文件 → 填表 → 出结论，视频几分钟能讲透

备选方向（文档版本影响分析等）留档于 `传智杯/05_参考资料/选题调研与备选方向.md`。

### 2. 技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite + TS + Tailwind | 中文资料多、上手快，3 人协作友好 |
| 后端 | Node + Express + TS | 与前端同语言，团队切换成本低 |
| 数据库 | SQLite（`node:sqlite`） | 零原生依赖，避免 Windows 上 better-sqlite3 编译问题 |
| 大模型 | DeepSeek `deepseek-chat` + `deepseek-reasoner` | 官方 API，支持 JSON Output；reasoner 用于复杂判定复核 |

### 3. 工程约定

- monorepo（pnpm workspace）：`web/` + `server/`
- 根 `pnpm dev` 同时起前后端；Vite 代理 `/api` → 8787
- `.env` 不入库，`.env.example` 入库
- 每次提交在 `docs/ai-log/` 留记录
