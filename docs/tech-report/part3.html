04AI 调用链路AI Pipeline

大模型只在开发期把政策原文编译成结构化条件树，运行期不调用。不确定的生成被限制在可人工复核的建库阶段， 用户看到的结论由规则引擎给出，可复现、可解释。

4.2提示词设计：把「解释政策」改成「编译政策」

系统提示词只有 9 条要求，但每一条都对应一个具体的失败模式。核心思路是先约束输出形态，再约束内容质量：

#提示词要求（原文摘要）它防的是什么
1只输出 JSON，不要 markdown 代码块、不要解释文字模型「先解释再输出」，导致解析失败
2每条条件必须回链原文：docRef 指向 section.id，quote 必须是原文句子（可截取不可改写）幻觉条款：凭空编一条原文里没有的条件
3条件必须可判定：field 点路径、operator 枚举、value 阈值/枚举输出「视情况而定」这类无法执行的软结论
4主观条件也抽成可判定条件，由用户自填是/否，不设 autoUncertain、不编造规则模型自作主张替用户判断「家庭经济困难」
5非硬性条件设 required:false，硬性门槛设 required:true把「择优参考」当成硬门槛，误伤用户
6组内 logic 取 all/any，多组默认顺序全部满足把「任一满足」写成「同时满足」，导致全员不符合
7忽略网页导航、页脚、联系方式把「扫一扫分享本页」抽成政策条款
8字段值用原文中文表述（全日制/本科/硕士），不擅自翻译成英文或数字枚举值与表单选项对不上，判定永远 unknown
9hints 面向用户：不满足时给一条可操作建议给出结论但不告诉用户下一步做什么

4.3结构化输出的三道闸门

模型输出不可能「一次就对」，所以建库脚本设计了三层防御，任何一层不通过都不会污染数据集：

① 协议层

response_format: json_object 强制 JSON；解析器额外兼容 ```json 围栏， 避免模型习惯性包裹代码块。

② 结构层

validatePolicy() 校验 9 类必填结构：id 一致、sections/conditions 非空、 field.type 与 operator 在枚举内、docRef 必须真实存在于 sections、logic 只能是 all/any。

③ 修正层

校验失败时，把「上一次模型输出」作为 assistant 消息、把错误清单作为下一条 user 消息， 要求模型修正后重新输出；最多 2 次尝试，仍失败则该政策不入库。

三层闸门的效果可以从日志里直接验证：37 次调用中，5 份政策在第 1 次未通过校验，带错误修正后全部通过，没有一份被丢弃。

错误来源模型的主要错误是条件之间的逻辑组合，不是单条条款

三条「判定逻辑修正」有一个共同点：每一条单独看都忠实于原文，但组合起来就错了。例如少数民族骨干计划原先把「报考硕士（年龄 ≤ 40）」 与「报考博士（年龄 ≤ 45）」写进同一个 all 组——对任何一个人，都不可能同时是硕士和博士，于是这份政策对所有人判为不符合。 这类错误不会被 JSON 结构校验发现，只能靠人读原文、对照判定结果才会暴露。这也是为什么项目坚持「AI 抽完必须人工复核」的原因。

5.5合规、隐私与免责

  • 个人信息最小化：表单只问这份政策真正用得到的字段；不收集手机号、身份证号等无关信息。
  • 填报内容不保存：判定页的表单只存在页面内存里，离开或刷新即清空；服务端只记录「判定过哪份政策、填了几项」。
  • 密钥不入库：DEEPSEEK_API_KEY 只放 .env（已 gitignore），运行期代码不引用；AI 日志不含请求头与 Key。
  • 不构成承诺：判定结果只是基于用户自填信息与政策原文的初筛，最终是否通过以学校与主管部门审核为准；页面与文档均显式声明。
  • 来源可溯：每份政策保留发布单位、发文字号、原文链接、年份与原文存档，用户可自行核对。

06判定引擎与横向能力Rule Engine

6.3三个容易被忽略的实现细节

① 模板比较

条件值可以写成 {{education.grade}}，求值时替换为另一个字段的值 —— 用于「毕业年份不早于入学年份 + 学制」这类字段间约束。 模板引用的字段没填时，该条件返回 unknown 而不是 fail。

② 空值语义

isEmpty() 把空串、空数组、null、undefined 统一视为「没填」； 未填条件一律 unknown。这条规则是整个产品体验的底线：留空不会被算成不符合。

③ 归一化比较

normalize() 去空格、统一大小写、全半角，toNumber() 兼容「10%」「10 名」这类带单位的写法 —— 避免「本科」与「本科 」被当成两个值。

6.4并列通道：一份政策里的「或者」

真实政策里大量存在「满足 A 或 B 即可」的结构。如果全部压成 all，就会把符合条件的人判成不符合。 系统用 channels 显式表达这种并列关系：通道内条件仍需满足，通道之间满足任一即可，通道之外的条件组照常全部满足。
