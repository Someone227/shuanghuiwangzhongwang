# 能申吗 · 政策资格匹配器

> 贴一份政策原文，30 秒知道自己够不够格 —— 逐条判定、差在哪、还缺什么材料。

奖助学金、专项补贴、保研推免、人才落户……这类政策文件动辄上万字，条件散落在正文、附件和脚注里。
用户真正的问题只有一个：**「我能申吗？」**

「能申吗」把这件事做成一条可验证的链路：把政策原文抽取成**结构化条件树**，用户填一张表单，
本地引擎逐条判定「符合 / 不符合（差在哪）/ 待补充」，每条结论都能点回原文的对应条款，
再附上材料清单与时间节点。

**在线演示**：<https://someone227.github.io/shuanghuiwangzhongwang/> —— 纯静态版，判定引擎直接在浏览器里跑，不需要后端、不需要 API Key，任何电脑打开就能用（见「在线演示版」小节）。

## 核心设计：大模型只在「建库」这一步用

这是本项目和「接个聊天框套壳」最大的区别：

| 阶段 | 谁在干活 | 是否消耗 token |
| --- | --- | --- |
| 开发期（建库） | DeepSeek 把政策原文抽取成条件树 JSON，人工逐条复核 | 一次性，每份政策约 1 次调用 |
| 运行期（判定） | 本地确定性引擎（纯函数）按条件树逐条比对 | **零 token，断网也能跑** |

这样设计的原因：

1. **现场演示不烧钱**：任何人克隆仓库、不配 Key 就能完整跑通判定（政策库已随仓库提交）。
2. **可复现、可测试**：判定结果只由「条件树 + 用户输入」决定，同一份输入永远同一份结论，54 个单元测试覆盖判定引擎、政策库数据契约、政策雷达与账号体系。
3. **可解释、可追溯**：每条条件都带原文段落引用（`docRef` + `quote`），测试断言每句 quote 都能在原文中逐字找到 —— 大模型没有编造条款的空间。
4. **过时条款不当成有效条件**：政策原文里的历史金额、试点省份等已失效条款不参与判定，页面顶部显式提示现行标准（如助学贷款额度此后已多次上调），不假装它还有效。

## 功能链路

| 步骤 | 做什么 |
| --- | --- |
| 1 政策入库 | 抓取官网原文，清洗站点导航与页脚噪声，保留段落偏移 |
| 2 AI 抽条件 | DeepSeek JSON Output 抽取条件树：字段、条件组、材料、时间节点 |
| 3 人工复核 | 校订偏移、标注过时条款、补充现行标准，`review` 字段留痕 |
| 4 填自己 | 按政策字段动态渲染表单，留空记为「待补充」而不是误判「不符合」 |
| 5 本地判定 | 逐条比对，给出符合/不符合/待补充 + 理由 + 差距 |
| 6 回链原文 | 每条判定可跳回原文对应段落高亮，另附材料清单与时间节点 |

## 页面

| 路径 | 页面 | 做什么 |

| `/login`、`/account` | 账号与个人中心 | 注册登录；个人中心汇总判定次数、覆盖政策、填到一半的政策、画像与资格概览，并可一键清空数据 |

## 界面主题

同一套组件支持两套配色，顶栏右上角的圆形按钮随时切换。选择记在本机（`localStorage`），首次打开跟随系统深色偏好；`index.html` 里有一段内联脚本在首帧前上色，深色用户不会先看到白屏。

| 主题 | 气质 | 配色 |
| --- | --- | --- |
| 青绿（浅色，默认） | 新中式、公益感、亲和 | 青绿 `#0f6f5c` + 朱红点缀 `#c2410c` + 米白纸面 `#f7f8f3`，标题左侧一道朱红竖线 |
| 午夜 AI（深色） | 科技感、冲击力，演示与录屏好看 | 亮青 `#38bdf8` + 靛紫 `#818cf8` + 深空底 `#080c16`，顶栏与首屏叠一层径向光晕 |

实现方式：颜色全部收敛成 CSS 变量（`web/src/style.css` 的 `@theme` 定义浅色、`html.dark` 覆盖深色），组件只写语义类名 `bg-surface` / `text-ink` / `border-line` / `text-on-brand`，深色模式不需要维护第二套组件。判定状态色（绿 / 红 / 黄 / 青）在深色下自动换成深底亮字，不需要逐处覆盖。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 前端 | Vue 3 + Vite 6 + TypeScript + Tailwind CSS v4 |
| 后端 | Node.js + Express 4 + TypeScript（tsx 运行） |
| 政策数据 | JSON 条件树（`data/policies/`），无数据库、无运行期外部依赖 |
| 判定引擎 | `server/src/domain/matcher.ts`：纯函数，支持 eq/ne/in/notIn/gte/lte/gt/lt/contains/exists 与字段间模板比较 |
| 大模型 | DeepSeek API `deepseek-chat`（JSON Output，temperature 0），仅用于开发期抽取 |
| 账号体系 | 账号与个人数据存服务端 JSON（`data/users.json`、`data/user-data.json`，均在 `.gitignore` 中）；密码 scrypt 加盐哈希；登录令牌为无状态 HMAC-SHA256 签名，多台设备可同时登录 |
| 测试 | `tsx --test`（判定引擎 + 政策库数据契约，覆盖条件判定、模板比较、原文回溯与噪声清洗） |
| 部署 | 双模式：本地开发走 Express 后端；`gh-pages` 分支发布纯静态版（政策 JSON 静态化 + 判定引擎打包进前端），由 `tools/deploy-pages.mjs` 发布 |

## 快速开始

> 前置：Node.js ≥ 20.19、pnpm ≥ 9

```bash
# 1. 安装依赖
pnpm install

# 2. 启动（前端 + 后端同时）
pnpm dev
```

- 前端：http://localhost:5173
- 后端：http://localhost:8787
- 健康检查：http://localhost:8787/api/health

### 在线演示版（纯静态）

同一份代码还能打成纯静态站点：政策 JSON 变成静态文件，`server/src/domain/matcher.ts` 这个纯函数判定引擎直接打包进浏览器运行 —— 零后端、零 token、断网也能判定。

- 线上地址：<https://someone227.github.io/shuanghuiwangzhongwang/>
- 本地构建与预览：

```bash
node server/scripts/export-static-data.mjs   # 导出政策 JSON 到 web/public/policies/
pnpm --filter web run build:pages            # 以 pages 模式构建（base=/shuanghuiwangzhongwang/）
pnpm --filter web run preview:pages          # 本地预览
```

- 发布（推到 `gh-pages` 分支，GitHub Pages 自动更新）：

```bash
node server/scripts/export-static-data.mjs
pnpm --filter web run build:pages
node tools/deploy-pages.mjs
```

静态版的限制：没有账号体系（登录、个人中心与判定记录只在后端模式下可用），其余功能（政策库、筛选搜索、逐条判定、原文回溯、政策雷达、申报日历）完全一致。

- **不登录也能完整使用判定功能**，登录只用于多设备共享判定记录。
- 同一局域网的其他电脑访问：前端已配置 `server.host = true`（监听所有网卡），用 `pnpm dev` 启动后，其他电脑访问 `http://<本机内网IP>:5173` 即可。

## AI 协同与可审计性

- **抽取留痕**：`docs/ai-log/policies/*.json` 保存每次调用的 messages、response 与 token 用量（不含请求头与 Key）。
- **不编造**：每条条件必须带 `docRef`（指向原文段落）与 `quote`（原文句子），测试断言 100% 可回溯。
- **人工复核**：`review` 字段记录复核时间、复核人与改动清单；历史金额/试点省份等过时条款不进入条件树，改写进 `notes` 的【现行标准】提示（如财教〔2024〕181号：国家奖学金 8000→10000 元/年）。
- **网页噪声清洗**：抓取原文会带上站点导航与页脚，脚本按固定正文起点截断并重算段落偏移，测试校验「原文只保留条款」。

## 开发约定

见 [AGENTS.md](./AGENTS.md)。要点：

1. **重大更改必须 commit 并同步到 GitHub**，保证随时可回档。
2. **细粒度提交**：每次提交对应一个功能模块或一次 AI 对话，禁止一次性提交全部功能。
3. `main` 分支任何时候都能跑起来；大改走 `feat/xxx` 分支。
4. API Key 只放 `.env`，永不入库。
5. 每次提交后在 `docs/ai-log/` 留一份协同记录。
